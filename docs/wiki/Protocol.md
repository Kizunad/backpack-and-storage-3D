# 通信和持久化

适用：`0.1.0-SNAPSHOT`，业务协议 **v6**、Framework wire **v2**、玩家保存格式 **3**、地面保存格式 **1**，未发布。唯一消息定义为 `shared/src/main/proto/volume.proto`；生成 Java 类不提交。

统一通道为 `kizuna_inventory_ui:message`，业务模块为 `bs3d:inventory`。玩家身份来自 Framework 认证连接，客户端不能选择其他玩家的库存。

| 消息 | 方向 | 语义 |
|---|---|---|
| `bs3d:open` | 客户端 → 服务器 | 获取当前连接会话与完整状态 |
| `bs3d:move` | 客户端 → 服务器 | 提交来源、目标、朝向、库存修订号和操作 UUID，开始计时转移 |
| `bs3d:equip` | 客户端 → 服务器 | 程序接口调整已穿戴容器的绝对位置，校验后原子保存 |
| `bs3d:cancel` | 客户端 → 服务器 | 取消指定会话的运行操作 |
| `bs3d:state` | 服务器 → 客户端 | 完整容器树、双手与盔甲展示栈、腰部上限、进度和声音 |
| `bs3d:appearance` | 服务器 → 客户端 | 本人与原版实体跟踪范围内玩家的装备外观，使用 `EquipmentAppearance` |
| `bs3d:ground_opened` | 服务器 → 客户端 | 原版右键校验成功并发送状态之后，通知打开指定地面内景 |
| `bs3d:close_ground` | 客户端 → 服务器 | 释放指定地面容器访问权；空列表释放当前连接全部地面容器 |

## 地面背包

放置、右键打开及空手潜行收回沿用原版方块交互包，客户端不能上传物品 NBT。放置要求手持单件容器并潜行，目标为有完整上表面支撑的可替换位置；服务端另行检查角色状态、5 方块内的交互距离、遮挡、世界边界、方块及实体碰撞和原版地形修改权限。创造模式也从手中移走原物品，不复制身份。

地面标记为 `bs3d:placed_bag`，区块仅保存容器身份、类型和朝向，客户端区块包不包含物品内容。右键成功后，服务器先把已授权的地面容器树加入 `State`，再发送 `GroundOpened`。`Container.grounded=true` 标识地面根容器，内部物品及嵌套容器继续使用原有内景和 `bs3d:move`。

`State.ground_revisions` 提供当前访问的地面根容器修订号；`MoveRequest.ground_revisions` 必须与它们一致，计时结束重新验证。同一背包只允许一位玩家访问，其他附近玩家可以在其释放后打开。当前连接最多保留 8 个地面根容器，和个人容器合起来仍受树大小限制。关闭内景、退出页面、断线、死亡、换维度、超距或失去视线时取消未提交操作并释放访问；最小化保留访问。

空手潜行右键收回时必须无人占用，整件物品连同内容回到交互手。放置、收回为即时原版交互，内景物品存取沿用计时转移。地面标记不能通过普通挖掘（含创造模式）或活塞移走；不注册另一个可复制内容的方块物品。

地面目录位于世界的 `data/bs3d/ground.dat`，包含完整容器实物、维度、位置、朝向和版本。涉及地面的提交先把完整玩家 NBT 和候选地面目录写入 `pending.dat` 并刷盘，再原子替换两份最终文件。日志提交点之后如果最终文件写入失败，停止服务并在下一次启动、玩家登录之前重放；日志之前失败则保留两端原库存。区块加载回调仅记录待恢复区块，在后续服务器 tick 重建或移除标记，避免加载回调递归等待自身。备份与恢复需要保留完整世界目录及 playerdata，不能只替换其中一侧。

## 世界装备外观

外观与本人库存使用不同的消息。`EquipmentAppearance` 每次完整替换一位玩家的可见装备，以 `player_uuid` 识别玩家，`entity_id` 和 `dimension` 共同限定当前实体，避免重生、切换维度或实体 ID 复用时显示旧装备。

`models` 中的 `WornModel` 仅包含注册物品 ID `item_type`、挂点 `mount`、连续腰角 `waist_angle_degrees`。不包含容器实例 UUID、容量、库存内容、物品名称或 ItemStack NBT；嵌套和手持容器不作为穿戴模型广播。空列表表示卸下全部容器，`removed=true` 表示停止跟踪并删除缓存。

Framework 握手完成后，即使尚未打开背包 UI 也同步本人和原版实体跟踪范围内的玩家。服务端仅在外观变化或开始跟踪时发送完整快照，离开视野、维度或服务器时撤销缓存，重新进入时补发。未提交的转移不改变外观；只修改包内物品也不会触发外观广播。客户端断线清空缓存。

客户端通过玩家 FeatureRenderer 复用 UI 的身体挂点，继承躯干动作、环境光和受伤叠色；世界中的包盖保持关闭，UI 开盖动画只影响预览。隐身和旁观者不显示容器模型，第一人称沿用原版身体不可见行为，按 F5 可查看自身装备。

## 容器身份与位置

每件容器是真实、不可堆叠的 ItemStack。类型 ID（例如 `bs3d:grass_pouch`）与实例 UUID 不同，移动实物时保留 UUID。`Container.id` 为实例 UUID，不再使用固定的 `pouch`、`basket` 作为实例身份。

坐标为 x=宽、y=从底部向上的高度、z=深度，单位为格。`Item.cell` 是闭开长方体的最小角。`Container.size` 是内部容量，`outer_size` 是整件物品的外部占格，两者独立。

| 类型 | 内部容量 | 外部占格 | 可装备位置 |
|---|---|---|---|
| 草包 | 1×2×2 | 2×2×2 | 连续腰环 |
| 背篓 | 3×3×3 | 3×3×4 | 胸前、背后 |
| 收纳箱 | 5×3×2 | 5×3×2 | 不可装备 |

`Container.worn=true` 表示直接装备于身体；`player_slot` 存在表示原版库存根槽；`parent` 非空表示处于另一容器中；`grounded=true` 表示已获准访问的地面根容器。这四种位置互斥。`State.items` 包括各内景的物品，以及 `container=worn` 的身体容器实物。地面根实物通过世界交互收回，不能当作内景物品取走；其内部物品可正常拖放。原版根容器由 `Container.player_slot` 定位，其手部展示栈由 `State.player_slots` 提供。

腰部角度 `waist_angle_degrees` 为 `[0,360)` 度，0 为正前，90 为玩家左侧。`WAIST_*` 枚举保留兼容旧挂点；省略角度时按对应旧位置换算，显式角度优先。胸背使用 `TORSO_FRONT`、`TORSO_BACK`，各允许一件；草包不能装备到胸背，背篓不能挂腰部。

`State.waist_limit` 为服务端玩家变量，默认 2，支持 0..16；0 禁止腰挂。普通客户端消息不能修改上限，管理接口见[扩展说明](Extension-Guide.md)。

## 转移请求

`MoveRequest.target` 为目标容器实例 UUID，或以下特殊值：

- `player`：放回原版库存。`target_player_slot` 存在时精确放入当前主手、副手或盔甲；省略时只在主背包自动找空位或合并。
- `worn`：将真实容器装备到身体，必须提供 `worn_target`。位置由服务端按物品类型与玩家上限校验。

从已存物品或身体容器移动时，`item` 引用实例 UUID。从原版来源移动时，`item` 为空，发送 `player_slot` 与开始拖动时真实栈的 SHA-256 指纹。客户端不上传 NBT、容量或尺寸创建库存。

原版槽号：主背包 0..35、靴子 36、护腿 37、胸甲 38、头部 39、副手 40。双手或盔甲直接互转时，来源和目标都必须属于当前双手/盔甲，必须显式指定不同的目标槽。UI 从角色骨架命中这些槽位，支持左右惯用手。

目标手仅接受空槽或能够完整合并的同种 NBT 栈，不交换、不部分合并、不溢出到其他槽。目标盔甲槽必须为空，数量为 1，且符合原版装备部位规则，包括鞘翅、南瓜与头颅。生存模式拒绝卸下绑定诅咒装备，创造模式遵循原版例外。

`State.player_slots` 为双手与四个盔甲槽的 `PlayerSlotStack`，沿用原 `hands` 字段号 6。空槽的 `stack_nbt` 为空。非空栈提供 `base_size` 供拖动预览；`unavailable_reason` 表示不可拖动，非法 NBT 不发送给客户端。原版换装、快捷栏变化、容器内容变化或创造状态变化也会主动同步，不增加业务修订号。

## 朝向、计时与取消

`MoveRequest.orientation` 与 `Item.orientation` 为 0..23 的正交朝向索引，0 为单位阵。`Item.base_size` 为未旋转尺寸，`Item.size` 为当前占格。服务端置换原始尺寸后验证边界和碰撞，同格旋转也需计时。收纳包使用注册类型的外部占格，不能靠旋转缩小体积。

索引与 `OrthogonalRotation` 一致：从单位阵出发，按先 Y 后 X 的顺序广度优先遍历去重。Y 正向 `(x,y,z) → (z,y,-x)`，X 正向 `(x,y,z) → (x,-z,y)`；新旋转左乘原朝向。反向为三次正向，24 种朝向无镜像，此索引不能重排。

开始时校验会话、修订号、来源、目标及容量，只构造候选。计时完成时重新读取并验证当前真实库存，在专用服务器主线程提交。相同操作 UUID 与相同载荷重试返回既有成功结果；同 UUID 不同载荷被拒绝。

运行状态包括 IDLE、RUNNING、COMPLETED、CANCELLED、REJECTED，每 2 tick 推送进度。角色行走与新转移被锁定；ESC、关闭界面、断线或角色失效取消尚未提交的操作，库存留在原位。关闭可以发生在开始回执之前，较早的 OPEN 快照不能清除在途 MOVE 身份。

`bs3d:equip` 保留给程序接入，只能移动已穿戴容器，使用绝对挂点和当前修订号。已处于请求位置则为空操作，否则原子保存并递增修订号。界面拖放使用带计时的 `bs3d:move`；运行中拒绝直接调整挂点。

## 保存与嵌套

真实容器 NBT 子字段 `bs3d_container` 包含 `id`（UUID）和 `contents`（`ContainerContents` 的 protobuf 字节数组）。子容器内容递归存在对应物品 NBT 中，因此取回手中、换装和再次收纳均携带完整内容。

禁止容器放进自身或子孙，同一玩家树中不得出现重复容器身份。根深度为 0，最大嵌套深度 4，整棵树最多 32 个容器；每层均校验几何。30 格收纳箱可以放草包，但背篓 3×3×4 在全部 24 朝向均放不下。

`SavedInventory.worn` 保存身体容器物品与位置，`waist_limit` 为可选玩家变量，缺省按 2 解释。原版根容器随原版 `Inventory` 保存。业务字段 `backpack_storage_3d` 与原版槽位在同一 playerdata 文件中，提交先写完整临时文件、刷盘再原子替换；不支持原子替换则拒绝事务并恢复内存。近期 128 个成功操作收据同时保存，运行中的操作不落盘。当前版本身体容器死亡保留；原版槽位遵循原版掉落规则。

单件 NBT 编码上限 16 KiB，业务存档上限 192 KiB；内容嵌套同样受栈大小限制。损坏存档拒绝读取，不静默清空。运行中获得损坏或重复身份的容器时拒绝业务视图和操作，保留原物品供管理员处理。

## 升级与 API 变化

业务消息 v6 增加地面打开/关闭消息、位置标记与地面修订号，两端需要同步升级，不能与 v4/v5 混用。v5 引入的 `bs3d:appearance` 继续保留。Framework 信封仍为 wire v2，protobuf 包名 `kizuna.backpack3d.v1` 保留。字段号不复用，玩家保存格式 3 无需额外迁移；没有地面目录的旧世界从空目录开始。

保存格式 1、2 在服务端读档时升级为 3：两个固定容器转换为真实草包、背篓，保留内容、朝向和挂点；下次保存写入新格式。新玩家不自动获赠容器。旧存档缺少 `base_size` 时只允许朝向 0，使用旧 `size`。新格式不可交给旧版写入。

客户端 `playerSlot()`、`movePlayerStack()` 和 `wear()` 分别提供原版槽快照、部位间转移与容器装备入口；`container(id)` 按实例 UUID 查询。公开 `Account.inventory()` 包含全部原版槽位，`selectedSlot()` 与新增 `creative()` 用于当前主手和绑定诅咒校验。`commit()` 必须将业务数据与完整原版候选原子保存。API 尚未冻结，集成方应以当前源码签名为准。

`Account.ground()` 和 `groundRevisions()` 缺省为空，原有个人库存适配器可保留原实现；支持地面容器时必须实现三参数 `commit(data, inventory, ground)` 的联合持久化。`ContainerTree` 新增接收地面根容器 Map 的构造方法，它们不属于原版额外槽位，也不进入 `SavedInventory.worn`。
